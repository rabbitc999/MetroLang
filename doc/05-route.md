# 路线规划：口径与实现

`metro-lang route` 在「方向 + 站」构成的图上跑 A*，权重是**真实出行时间**（秒），
不是站数或几何距离。本文说明每个数字从哪来，以及为什么这样取。

## 1. 图的构造

节点是 `方向 ID \x1f 站名` 的拼接串。为什么不用纯站名？因为同一条线路的正反两个
方向、不同线路在换乘站的站台，它们的**可达性不同**：从「2号线 嘉禾望岗→广州南站」
方向的车上下不来直接换 3 号线，得看那个方向是否停这一站。

两类边：

### 运行边

同方向相邻站，`cost = 区间运行时间 + 出发站停站时间`。

- **只加出发站**的停站，不加到达站的：到达站的等待属于下一段，这样各段相加不会重复。
- 区间运行时间来自 `src/train_time.cpp` 的物理模型（Davis 阻力 + 恒功率牵引 + 数值积分），
  详见 `doc/03-travel-time-model.md`。
- 有 `SPEED_LIMIT_DEFINE` 时该区间用限速，否则用线路 `MAXSPEED`。

### 换乘边

同站跨线路，`cost = 步行时间 + 等下一趟车 + 惩罚项`。

| 分量 | 取值 |
|---|---|
| 站内换乘 | `TRANSFER_TIME`（默认 180 s） |
| 出站换乘 | `OUT_STATION_TRANSFER_TIME`（默认 300 s） |
| 惩罚项 | `--transfer-penalty`，默认 0；`--fewer-transfers` 时调大 |
| 等车 | 见 §2 |

**换乘状态判定**要做大小写归一：数据里 `TRANSFER_TYPE` 的 `STATUS` 常写成
`OPERATING`（大写），早期实现拿它和 `"operating"` 直接比，比较失败导致换乘边被丢弃，
路线于是绕远。这一处曾造成广州南站→机场南多坐 14 分钟，排查时先确认"建图是否正确"
再怀疑搜索算法。

## 2. 候车时间

$$E[W] = \frac{T}{2} + t + (C-1)\,T$$

- $T$：当前时刻的发车间隔，来自 `HEADWAY_PROFILE` 的分时段表（第一条命中生效）；
- $t$：`AVG_BOARD_TIME`（平均上车时间，默认 3 s）；
- $C$：当前时刻的拥挤度，来自 `CROWD_PROFILE`（≥ 1.0，表示平均要多等几趟）。

起点等一趟，**每次换乘各等一趟**。这是与 metro_editor 的 C# 实现对齐的关键点：
早期版本换乘边没计等车，A* 就会把「多换乘、短段落」当成捷径，选出一条
换乘 3 次但每段都很短的荒谬路线。

## 3. 总出行时间

$$T_{\text{total}} = \underbrace{\sum \text{运行}}_{\text{乘车}} + \underbrace{\sum \text{换乘步行}}_{\text{换乘}} + \underbrace{\sum E[W]}_{\text{候车}} + \underbrace{2 \times \text{ENTRY\_TIME}}_{\text{进出站}}$$

进出站算两次：进站一次、出站一次。`summary` 里四个分量分别给出，加起来恒等于
`total_seconds`（`tests/test_numeric.py` 有断言守着这个恒等式）。

## 4. 启发式

A* 的启发式是**球面距离 ÷ 全网最高速度**，一定不高估，所以结果仍然最优。
弹出时校验过期项（堆里可能残留同一个键的更差副本），否则会多算一条边。

## 5. 票价

`src/fare.cpp`。普通段按**合并总里程**结算（不是分段相加），顺序是：

1. 命中 `SEGMENT lo hi fare` 阶梯 → 取该档；
2. 超出最高档且配了 `LINEAR_EXTENSION` → `base + (km - threshold) × rate`；
3. 都没命中 → `DEFAULT_FARE`；
4. 有 `FARE_CAP` 则封顶。

特殊线路优先于普通计价：

- `SPECIAL_LINE 线路 ALL 票价`：整条线一口价（机场线这类）；
- `SPECIAL_LINE 线路 SEGMENT '起' '终' 票价`：区段附加费（大兴机场线这类），
  按经过的区段累加。

`--no-special` 可以把特殊线路关掉，用来看"如果按普通计价要多少钱"。

## 6. 区间距离的两个来源

数据里每个站可以带 `next`（本站到下一站的实测里程）。写 `DISTANCE AUTO` 时由两端
坐标算球面距离补上。

> **踩过的坑**：`REV` 语法（`DIRECTION_DEFINE G1_1 REV G1_0`）反转站序时，距离必须
> 跟着一起反转——反转后第 `i` 段等于原来第 `n-2-i` 段。早期实现用「往后搬一位」的
> 写法，结果每一条反向线路的**倒数第二段距离被清零**，明细里程系统性偏短。修复后
> 公园前→广州东站从 7.67 km 变成 8.51 km，与源数据逐段求和完全一致。

另外，明细汇总早期按「站名 → 下一站距离」查表，反向走同一段时查不到就退回球面距离，
与建边用的数不一致。现在 `DirInfo::segKm` 把区间距离**双向登记**，建边和明细用同一份。

## 7. 输出

```text
$ metro-lang route 广州.m --from 广州南站 --to 机场南(T1)
广州南站 → 机场南(T1)
  1. 2号线（开往 嘉禾望岗）
     广州南站 → 嘉禾望岗，23 站 / 30.38 km / 43 分 11 秒
  2. 3号线（开往 机场北(T2)）
     嘉禾望岗 → 机场南(T1)，4 站 / 15.14 km / 11 分 4 秒
合计：47.2 km，换乘 1 次，27 站
      乘车 54 分 15 秒 + 换乘步行 2 分 0 秒 + 候车 5 分 6 秒 + 进出站 4 分 0 秒
      总计 1 小时 5 分 21 秒（按 11:29 的发车间隔）
票价：9 元（按里程阶梯计价（15 档，超过 104 km 每公里 0.12 元）；普通里程 47.2 km）
```

`--json` 给出同一份数据的结构化版本（`summary` / `segments` / `stations` / `guidance`），
字段名与 `doc/02-json-format.md` 一致。

## 8. 查看器里的轻量寻路

`map_view` 是纯前端，没有运行时间与发车间隔数据，所以它用**区间距离**当权重：

- 运行边 = 相邻站实测距离（缺坐标时用球面距离，再退 1 km）；
- 换乘边 = 固定 6 km（约等于"换乘一次 ≈ 多坐三四站"）。

`metro_mapcore.js` 的 `findRoute(model, from, to)` 是纯函数，浏览器与单元测试共用。
它给出的是**线路选择**与**近似里程**，不报秒数与票价。为了保证不跑偏，
`map_view/test/mapcore.js` 会拿 CLI 的实时结果做对照：四组典型 OD 的线路序列必须
完全一致，里程偏差必须小于 5%（实测 0.0%–0.7%）。

精确规划始终以 `metro-lang route` / LSP `metro/route` 为准。
